When any check in the pipeline decides a message shouldn't go straight to the inbox -- a failed DMARC policy, a malicious attachment, a high BEC score -- it doesn't just vanish. It lands in a quarantine queue for a human (usually an IT admin, sometimes the recipient themselves via a daily digest email) to review, release, or permanently deny.

This console mirrors that admin experience: every held message shows why it was held, and you can release it (deliver it after all -- useful for false positives) or deny it (confirm the block). Send messages from the Compose page or Attack Simulator that trip DMARC or a gateway check to see them appear here.
