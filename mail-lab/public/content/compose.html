This is the flagship lab: compose a real message, choose how it's sent, and watch it go through the same authentication pipeline a real mail server would run -- SPF against the envelope sender's IP, DKIM verification, DMARC alignment, and (optionally) an ARC-sealed forwarding hop.

Try these experiments once you've set up a domain in the DNS Zone Manager:

  • Legitimate send: set the envelope-from and header-from to the same domain you configured SPF/DKIM/DMARC for, use the sending IP your SPF record allows, and sign with DKIM. Should pass cleanly.
  • Spoofing attempt: set the header-From to your configured domain but send from an unauthorized IP with no DKIM signature. Watch SPF fail and DMARC reject it.
  • Envelope/header mismatch: use a different domain for the envelope-from than the header-From. Notice SPF can technically "pass" for the envelope domain, yet DMARC still fails because that domain isn't aligned with what the recipient sees.
  • Forwarding: tick "simulate mailing list forward" and watch ARC preserve the original trust decision even after the message is modified downstream.

The result panel shows the exact Authentication-Results and Received headers a real mail client's "Show Original" view would display.
