None of SPF, DKIM, or DMARC check the display name a mail client shows -- only the underlying email address. That leaves a wide-open attack: send from any address you control, but set your display name to "Jane CEO". On a phone, many mail apps show only the display name by default, so the recipient never even sees the real address.

Secure email gateways address this the same way you can here: maintain a directory of known, trusted names and their real addresses, and flag any inbound mail where the display name matches someone trusted but the address doesn't. This catches CEO-fraud and vendor-impersonation attempts that sail right through SPF/DKIM/DMARC, because the attacker's own domain can be perfectly well-authenticated -- it's just not who it claims to be.
