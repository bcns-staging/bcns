Everything in this lab is a separate tool you configure by hand -- the real test of whether it all adds up to a working defense is to actually attack your own configuration and see what happens. That's what this page does: pre-built scenarios modeled on real attack patterns, run against whichever domain you've set up.

Three of the four scenarios are genuine attacks -- a "caught" result means your configuration correctly blocked or quarantined them. The fourth (legitimate mailing-list forwarding) is a deliberate control case: it's not an attack, and a well-configured defense (specifically, ARC) should let it through despite its native SPF/DKIM breaking. A gateway that can't tell the difference between "attack" and "legitimate but authentication-breaking" isn't actually useful -- it just blocks everything.

Try running each scenario before configuring any defenses, then again after setting up SPF/DKIM/DMARC, known contacts, and protected domains, to see the difference your configuration makes.
