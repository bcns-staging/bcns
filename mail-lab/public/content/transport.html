SMTP was not designed with encryption in mind. STARTTLS retrofits it: a sending server connects in plaintext, then upgrades the connection to TLS mid-conversation before any message content is sent.

👋
EHLO
Sender greets the receiving server
→
📋
Server Offers STARTTLS
Advertises TLS support (or an attacker strips this line)
→
Upgrade to TLS
Rest of the conversation is encrypted
No STARTTLS
Silently continues in plaintext — no warning

The problem is that STARTTLS is opportunistic -- if the receiving server doesn't advertise it, or an on-path attacker simply deletes the "250-STARTTLS" line from the server's response (a "STRIPTLS" attack), the sending server just... continues in plaintext. No error, no warning, no retry. Run the simulation below both ways and compare.

This exact weakness is why MTA-STS and DANE exist: both make TLS mandatory for a domain instead of best-effort.
