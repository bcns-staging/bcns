Exact Data Match (EDM) is the technique enterprises use when they know exactly which records are sensitive -- an actual customer database, an employee roster -- rather than relying on a value merely looking sensitive. Instead of "does this look like an SSN," EDM asks "is this the exact SSN of a real person in our database."

Why hashing, not plaintext

A naive implementation would upload the sensitive database to the DLP tool as-is -- creating a second copy of the exact data you're trying to protect. Real EDM systems instead compute a salted one-way hash of each (normalized) value and only ever store and compare hashes. Content being scanned is normalized and hashed the same way; if the hashes match, you know the original values matched too, without either side ever needing the plaintext again.

Composite vs. single-field matches

Matching just a name, or just a number, in isolation is weak evidence -- common names and account-number-shaped numbers appear all the time by coincidence. Matching multiple fields from the same record together (a name and its SSN, appearing near each other) is much stronger evidence, and is scored accordingly here.
