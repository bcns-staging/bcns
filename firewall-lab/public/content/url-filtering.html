URL filtering categorizes web destinations (gambling, malware, news, business apps...) and lets policy act on the category -- independent of App-ID. The same "generic-tls" web-browsing app can lead to a business tool or a gambling site; App-ID alone can't tell them apart, only the destination's category can.

Because it's a separate signal, a rule can allow the application (web browsing) while still blocking specific categories within it -- exactly what the seeded "Allow Inspected Web Browsing" rule's content inspection does for the malware and gambling categories, overriding the rule's own "allow" action when it sees them.
