Every rule you write later references these objects instead of raw IPs typed inline -- zones group interfaces by trust level (Trust, Untrust, DMZ), interfaces are the physical ports traffic actually arrives on, hosts are named endpoints, and services are named protocol/port combinations. This mirrors how every real firewall platform organizes policy -- nobody writes "allow 10.0.0.0/24 to 0.0.0.0/0 tcp/443" by hand at scale.

A small starter environment is already seeded below: a Trust zone for internal workstations, an Untrust zone for the internet, and a DMZ for the one published web server -- the three-zone layout most of this lab's examples and preset scenarios assume.
