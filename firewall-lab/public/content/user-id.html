Writing policy against IP addresses breaks down fast: laptops move between subnets, DHCP leases change, and "10.0.0.50" tells you nothing about who's actually using it. User-ID solves this by mapping IP addresses to real identities -- typically fed by Active Directory login events, a captive portal, or an agent on the endpoint -- so policy can be written against users and groups instead.

This is what makes a rule like "the finance group can reach the finance SaaS app, nobody else can" possible without maintaining a brittle, constantly-stale list of finance team members' current IP addresses.
