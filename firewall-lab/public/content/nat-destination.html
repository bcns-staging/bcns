Destination NAT (port forwarding) publishes an internal server on a public IP: a connection to the firewall's public address on a given port gets silently rewritten to an internal IP/port before it's routed onward -- the classic way a DMZ web server gets reached from the internet.

The gotcha: which address does the security rule see?

NAT and security-policy lookup are two separate steps, and vendors disagree about their order. Some evaluate the security rule against the original ("pre-NAT") destination -- the public IP you actually wrote the DNAT rule for. Others evaluate it against the translated ("post-NAT") destination -- the real internal IP. If your rule base was written assuming one behavior and the platform actually does the other, traffic you expected to allow gets silently dropped -- a genuinely common, confusing real-world misconfiguration.
