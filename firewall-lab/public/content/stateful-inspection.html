A stateless packet filter checks every packet against the rule base independently -- including the return traffic of a connection you already allowed, which means you'd need a matching inbound rule too. A stateful firewall instead tracks open connections in a session table: once the first packet of a NEW connection is permitted, every subsequent packet in that same conversation -- in either direction -- is auto-permitted as ESTABLISHED traffic, without walking the rule base again.

RELATED traffic: the FTP problem

Some protocols open a second connection as a side effect of the first. Classic (active-mode) FTP is the textbook case: the client opens a control channel to the server on port 21, and the server then opens a separate data connection back to the client on a random port. That data channel arrives from the outside, to a port nobody wrote a rule for -- a stateless filter would drop it. A stateful firewall instead recognizes it as RELATED to the already-open control session and permits it automatically.
