A rule is shadowed when an earlier rule already matches every connection it would ever match. Because of first-match-wins, the shadowed rule can never fire -- it's dead weight at best, and a real security gap at worst if the two rules don't share the same action.

Two ways this bites you
Same action
just redundant -- safe to delete
Different action
a real gap: the narrower, more-intended rule never gets a chance to run

This is a real, common finding in production rule-base audits -- especially after years of rules being added to the top "just to be safe" without anyone checking what's already covered further down.
