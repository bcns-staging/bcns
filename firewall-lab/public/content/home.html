A firewall's job has stayed the same since the first packet filters shipped: decide, for every connection that wants to cross a boundary, whether it's allowed. What's changed dramatically over time is what information that decision gets to use.

This lab is split into two halves that mirror that history. Part 1 (Traditional Firewall) covers the stateful, port-and-IP-based model that's still the backbone of every firewall's fast path today. Part 2 (NGFW) covers what got layered on top: identifying the real application and user regardless of port, and inspecting content -- even encrypted content -- before deciding.

What each generation gets to see
Traditional

→
allow / deny
NGFW
everything Traditional sees, plus: real application (App-ID), real user/group (User-ID), decrypted content (SSL decrypt), threat intel, IPS, URL category, files
→
allow / deny
a much more informed decision

Every page runs against a small seeded environment (three zones, a handful of hosts, two independent rulebases) so you can test real traffic immediately -- though every object is fully editable on the Network Objects and Rule Builder pages.
