A traditional rule can only ask "what port is this on." App-ID asks a fundamentally different question: "what application is this, regardless of port," by inspecting the traffic's actual signature and behavior rather than trusting what it claims to be.

This matters because plenty of applications deliberately (or incidentally) run over port 443 to blend in with ordinary web traffic -- P2P clients, tunneling tools, even malware command-and-control. A port-based rule that allows "tcp/443" allows all of them. An App-ID-aware rule can single out the real application and block just that.
